## 💡 Best Practices

### Load Instructions In This Order

1. **ALWAYS (every session):**
   - `.copilot/instructions.md` (required)
   - `.copilot/code-standards.md` (required)

2. **When relevant:**
   - `.copilot/domains/testing.md` (if writing tests)
   - `.copilot/domains/cmake.md` (if modifying build)
   - `.copilot/domains/architecture.md` (if designing)
   - Module-specific: `domains/session.md`, `domains/connection.md`, etc.

### Pro Tips

✅ **Load instructions once per session** (they persist in context)  
✅ **Load domain files as needed** (just paste content or use /load)  
✅ **VSCode auto-loads** on startup (no manual action needed)  
✅ **Minimal tokens** (all files compressed, ~200 tokens each)  
✅ **Save context** (can load all core files and still have room)  

### Don't Do

❌ Load files you don't need (wastes tokens)  
❌ Load same file twice (once per session is enough)  
❌ Ignore instructions (they're there for a reason)  
❌ Mix multiple projects' instructions (stay focused)

## 🔧 VSCode Auto-Integration

File: `.vscode/settings.json`

```json
{
  "github.copilot.enable": true,  // Copilot enabled
  "[cpp]": {
	"editor.defaultFormatter": "ms-vscode.cpptools",
	"editor.rulers": [100, 120]
  },
  "cmake.generator": "Visual Studio 17 2022",
  "cmake.buildDirectory": "${workspaceFolder}/build/windows-debug"
}
```

✅ Copilot auto-loads `.copilot/` directory  
✅ VSCode auto-formats C++ (clang-format)  
✅ CMake configured for efficient builds  
✅ Rulers show line limits (80, 120 columns)
